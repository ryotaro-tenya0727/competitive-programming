# コミットしてプッシュ

このリポジトリでコミットとプッシュを依頼されたときに使う。`$git-commit-push` の明示的な呼び出しも両方の依頼として扱う。コミットだけの依頼ではプッシュしない。

1. 現在のブランチ、upstream、remote、`git status --short`、ステージ済みと未ステージの差分を確認する。未追跡ファイルは追加前に内容を確認する。依頼に含まれるファイルを特定し、対象が曖昧な場合や無関係なステージ済み変更が混ざる場合は、コミット前にユーザーへ範囲を確認する。
2. 変更に応じた検証を実行する。対象のパスだけを削除分も含めてステージし、`git diff --cached --stat`、`git diff --cached`、`git diff --cached --check` を確認する。空の差分、認証情報、生成物、無関係な変更はコミットしない。
3. 実際の変更を表す簡潔なコミットメッセージを付ける。参考になる場合は直近のコミットの書式に合わせ、確認済みの変更をコミットする。この依頼でコミットとプッシュの両方が承認されていれば、再確認せずプッシュまで進める。
4. 現在のブランチに設定された upstream へプッシュする。upstream がない場合は宛先の remote とブランチを確認し、明確なら `git push -u <remote> HEAD` を使う。force push や履歴の書き換えは行わない。認証、権限、non-fast-forward によって失敗した場合は、原因とローカルコミットを報告し、成功したと表現しない。
5. コミットハッシュとメッセージ、プッシュ先のブランチと remote、実施した検証、作業ツリーに残る変更を報告する。ローカルコミットとプッシュの成否を区別する。
